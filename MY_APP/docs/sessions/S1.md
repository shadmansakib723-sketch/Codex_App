### Screens and layout

- Three bottom tabs: Home, Friends, and Profile.
- Home has a fixed, full-width 4:3 artwork area. It starts at the top without
  adding status-bar safe-area padding, so artwork can sit behind the visible
  dark status-bar icons.
- The artwork is currently an empty colored area. The layout accepts an
  optional image and uses `contain` so a supplied image is not cropped or
  stretched. The originally recommended artwork source was 1200 × 900.
- A light panel overlaps the artwork by 12 layout units and has rounded top
  corners. Only its contents scroll; the artwork and panel edge remain fixed.
- The bottom bar is a normal navigator footer, outside the Home scroll area.
  It reserves space so the content does not run underneath it.
- Home cards and artwork details have not been specified or added. Friends
  and Profile are deliberately empty, not broken completed features.
- The empty Home panel does not currently provide overflowing content with
  which to demonstrate independent scrolling on a device.

Do not invent artwork text, illustrations, statistics, prayer tracking, friend

## Bottom navigation — final inspected state

The white pill has a thin border, subtle native shadow, and a light-gray
selected bubble. Text and icons are dark charcoal when selected and muted
gray otherwise. Expo Router owns the selected tab; there is no separate global
navigation store.

- Icons: Home `home-outline`, Friends `people`, Profile `person-circle-outline`.
- Icon size and box: 24; decorative icons do not scale with system text.
- Labels: Poppins Medium, size 12, line height 16. Text scaling remains enabled.
- Minimum tab touch height: 52, not a fixed height, allowing larger text to grow.
- Icon/label gap: 2. Tab vertical padding: 4. Pill padding: 4 plus its border.
- Normal pill height is approximately 62 layout units, not a guaranteed physical
  pixel measurement. Earlier versions were approximately 86, then 74.
- Side spacing: 24 plus the corresponding safe-area inset. Maximum width: 400.
- Space above the pill: 8.
- Current bottom spacing is **`Math.max(insets.bottom, 12) + 7`**.

The current source has `+ 7`; the old note 13 recorded the earlier `+ 8` change.
The source was re-read before this handoff and was not changed during
consolidation. Preserve the current value. To raise/lower the bar, change only
the final added number: a larger number raises it, a smaller number lowers it.
Leave the safe-area calculation intact. This is normal footer spacing, not a
transform that lets content overlap the bar.

### Bubble behavior and a regression not to reintroduce

The inner row is measured, then divided equally among the three routes. One
bubble slides horizontally behind the buttons over 240 ms with eased timing.
It follows the navigator's active index, respects reduced motion, accounts for
right-to-left positioning, and does not intercept touches or add screen-reader
content. Normal cancellable tab-press and long-press events are preserved.

The first animated version made the bubble disappear on the user's device.
The cause was reproduced using the installed libraries' style-merging helper
and Reanimated prop filter: wrapping the animated view in NativeWind
`cssInterop` combined ordinary styles and an animation handle. Reanimated then
kept the animated transform but dropped the combined background, width, and
positioning.

The current fix deliberately separates them:

1. The moving `Animated.View` has `cssInterop={false}` and receives native
   container positioning, measured width, and animated movement as separate
   style entries.
2. A plain child View fills that container and uses NativeWind for its rounded
   shape and selected background.
3. The Ionicons component still uses its small NativeWind adapter; that is
   separate from the animated container and should not be removed for this fix.

Do not remove this separation merely to make every style a class name. The
small native container style is justified by the verified integration problem.
Code checks and focused reproduction passed after the fix, but the user has
not explicitly confirmed the bubble's final appearance since that correction.
Do not convert a later spacing request into proof of that visual result.

If adding a future tab, update both the router and the bar's label/icon
metadata. The current width calculation counts all routes while unknown
metadata is skipped; an unconfigured extra route can misalign the bubble.
