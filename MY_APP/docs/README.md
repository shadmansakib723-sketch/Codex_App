# Chat Handoffs

Keep one Markdown file per actual chat in `docs/sessions/`:

- [S1 — Foundation and bottom navigation](C:/Users/SAKIB/plz/MY_APP/docs/sessions/S1.md)
  consolidates all 13 earlier change notes from the first long chat.
- A new chat will use `S2.md`, then `S3.md`, and so on. Those future files do
  not need to be created before the chats begin.

Read `agent.md` first, then the latest handoff (compare the numbers, not their
alphabetical order). Also read a particular handoff when the user names it.
Within the same chat, update that chat's existing file instead of creating a
new summary for every small task.

Each handoff should explain the current state, changes and decisions, checks
that actually passed, user-reported results, what remains unknown, and useful
next steps. Do not treat an old successful check as proof of newer changes.

The 13 old `session-summary-N.md` files were consolidated and removed at the
user's request. Their useful history is preserved in S1; it is not a verbatim
archive of each original. Do not recreate that old per-change numbering.

Preserve previous chat handoffs unless the user requests reorganization or
deletion. After documentation changes, open the created/edited files in Codex
as requested by the user.
